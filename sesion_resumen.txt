¿QUÉ ES EL PROYECTO?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

UMarket es un marketplace exclusivo para estudiantes universitarios guatemaltecos.
Solo pueden registrarse usuarios con correo institucional (.edu) de universidades
guatemaltecas. La verificación de email es el diferenciador principal: genera
confianza entre compradores y vendedores.

Stack tecnológico:
  - Spring Boot 4.0 (Java 21)
  - MySQL (base de datos local)
  - Spring Security + JWT (autenticación)
  - Cloudinary (almacenamiento de imágenes)
  - Spring Mail / Gmail SMTP (correos de verificación)
  - Lombok (reducción de código repetitivo)
  - Maven (build tool)

Funcionalidades:
  - Registro y verificación de correo .edu
  - Login con JWT
  - Publicaciones (listings) con hasta 5 imágenes
  - Categorías
  - Mensajería entre usuarios
  - Reseñas con calificación 1-5

ERRORES ENCONTRADOS (antes de los cambios)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. CRÍTICO — Clave JWT hardcodeada en el código
   Archivo: security/JwtUtil.java
   Antes:   private static final String SECRET = "umarket-clave-secreta-...";
   Riesgo:  Cualquiera con acceso al código puede falsificar tokens JWT.

2. CRÍTICO — Login no verificaba si el usuario confirmó su correo
   Archivo: controller/AuthController.java
   Antes:   El login generaba el token sin revisar el campo "verificado".
   Riesgo:  Un usuario podía saltarse la verificación de correo y entrar igual.

3. ALTO — @CrossOrigin("*") en todos los controllers
   Archivos: Todos los controllers
   Antes:   Cada controller tenía @CrossOrigin(origins = "*") que sobrescribía
            la configuración segura de SecurityConfig.
   Riesgo:  Cualquier sitio web podía hacer peticiones a la API.

4. ALTO — vendedorId, remitenteId y autorId venían como query params
   Archivos: PublicacionController, MensajeController, ResenaController
   Antes:   POST /api/publicaciones?vendedorId=1
            POST /api/mensajes?remitenteId=1&destinatarioId=2
            POST /api/resenas?autorId=1&vendedorId=2
   Riesgo:  Cualquier usuario podía poner el ID de otra persona y actuar en su nombre.

5. ALTO — Cualquier usuario podía subir imágenes a publicaciones ajenas
   Archivo: controller/ImagenController.java
   Antes:   No se verificaba si el usuario era dueño de la publicación.
   Riesgo:  Un usuario podía modificar las imágenes de otro vendedor.

6. ALTO — Cualquier usuario podía modificar o desactivar cuentas ajenas
   Archivo: controller/UsuarioController.java
   Antes:   PUT /api/usuarios/{id} y DELETE /api/usuarios/{id} sin verificar
            que el usuario autenticado sea el dueño de esa cuenta.

7. ALTO — Bug: mensajes fallaban al guardarse (publicacion_id NOT NULL)
   Archivo: service/MensajeService.java
   Antes:   El método enviar() nunca asignaba la publicación al mensaje,
            pero la tabla mensajes tiene publicacion_id NOT NULL.
   Riesgo:  Cada intento de enviar un mensaje fallaba con error de base de datos.

8. MEDIO — Endpoints de bandeja de mensajes exponían ID del usuario en la URL
   Archivo: controller/MensajeController.java
   Antes:   GET /api/mensajes/bandeja/{usuarioId}
            GET /api/mensajes/noleidos/{usuarioId}
   Riesgo:  Cualquier usuario autenticado podía ver la bandeja de otro.

9. MEDIO — Campos sensibles expuestos en respuestas JSON
   Archivo: model/Usuario.java
   Antes:   La contraseña (hasheada), el token de verificación y su fecha de
            expiración se devolvían en las respuestas de la API.

10. MEDIO — URL de verificación hardcodeada como localhost
    Archivo: service/EmailService.java
    Antes:   String enlace = "http://localhost:8080/api/usuarios/verificar?token=...";
    Riesgo:  En producción los correos de verificación envían a localhost y no funcionan.

11. MEDIO — Endpoints de imágenes eran públicos (sin JWT)
    Archivo: security/SecurityConfig.java
    Antes:   "/api/imagenes/subir" y "/api/imagenes/publicacion/**" estaban en
             la lista de endpoints sin autenticación.

12. BAJO — CloudinaryService aceptaba cualquier tipo de archivo
    Archivo: service/CloudinaryService.java
    Antes:   No se validaba que el archivo fuera una imagen antes de subirlo.

13. APARTE — Límite de 3 publicaciones gratuitas (freemium)
    Archivo: service/PublicacionService.java, repository/PublicacionRepository.java
    Antes:   Había una constante PUBLICACIONES_GRATIS = 3 que bloqueaba al usuario
             al llegar a ese número con mensaje de "UMarket Premium".
    Decisión: El usuario decidió quitarlo — monetización pendiente de definir.

CAMBIOS DE API QUE DEBES ACTUALIZAR EN POSTMAN
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ANTES                                          AHORA
  ─────────────────────────────────────────────────────────────────────────────
  POST /api/publicaciones?vendedorId=1     →  POST /api/publicaciones
  DELETE /api/publicaciones/1?vendedorId=1 →  DELETE /api/publicaciones/1
  POST /api/mensajes?remitenteId=1&...     →  POST /api/mensajes?destinatarioId=2&publicacionId=5

  GET /api/mensajes/noleidos/{usuarioId}   →  GET /api/mensajes/noleidos

  En todos los endpoints protegidos siempre debes mandar el header:
    Authorization: Bearer <token_jwt>
